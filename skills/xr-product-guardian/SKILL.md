# Skill: XR Product Guardian

## Use when
Planning features, changing the gameplay loop, or reviewing scope.

## Read first
- AGENTS.md
- docs/xr/PRODUCT_THESIS.md
- docs/xr/DECISIONS.md
- docs/xr/ROADMAP.md

## Procedure
1. State the player-facing problem.
2. Identify the current milestone.
3. Ask whether the proposal improves:
   - meaningful decision;
   - physical legibility;
   - interaction satisfaction.
4. Check whether it duplicates an out-of-scope system.
5. Classify claim as evidence, hypothesis or preference.
6. If hypothesis, define the cheapest experiment.
7. Reject work that does not advance the current gate.

## Output
- decision: BUILD / TEST / BACKLOG / REJECT;
- one-sentence reason;
- evidence needed;
- smallest next slice.

## Failure modes
- adding realism because it is "industrial engineering";
- adding systems before interaction is proven;
- using technical vocabulary as gameplay;
- treating competition novelty as a substitute for fun.

## Stop condition
A scoped, testable next action exists or the proposal is explicitly backlogged.
