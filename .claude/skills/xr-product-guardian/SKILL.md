# Skill: XR Product Guardian

## Read first
- AGENTS.md
- docs/xr/PRODUCT_THESIS.md

- docs/xr/COMPETITION_SCORECARD.md

## Procedure
1. State the player-facing problem.
2. Identify the current gate.
3. Identify whether this is:
   - signature interaction;
   - magic moment/feedback;
   - sensory identity;
   - strategy/progression.
4. Name the official 25% criterion it improves.
5. State what polish/test work it displaces.
6. Classify claim: evidence / hypothesis / preference.
7. If hypothesis, define cheapest experiment.
8. Apply scope:
   - Tier 0 first;
   - Tier 1 only when core remains safe;
   - optional stretch requires owner score-per-hour authorization.
9. Check competitor overlap (especially Traffix XR / Loop One: Done).
10. Reject award-category shopping.

## Output
BUILD / TEST / BACKLOG / REJECT
+ reason
+ evidence needed
+ smallest next slice

## Automatic rejection patterns
- "winner X had it";
- "this could qualify for another award";
- realism for realism's sake;
- feature added before integrated walking skeleton;
- new currency/menu/system with no near-term decision value;
- work that makes the product resemble automation sandbox or traffic puzzle more than industrial crisis strategy.

## Stop condition
A testable next action exists or feature is explicitly backlogged.
