# XR Competition Roadmap

Status legend: TODO / DOING / BLOCKED / DONE / KILLED

## Phase 0 — Foundation
Status: DOING

Deliverables:
- [x] product thesis
- [x] agent rules
- [x] decision log
- [x] experiment register
- [x] competition checklist
- [x] harness scaffold
- [x] skill system scaffold
- [ ] Meta VR Start approval
- [ ] Devpost registration confirmed
- [ ] target headset access arranged
- [ ] XR stack kill-test branch/app initialized

Exit gate:
The team can start technical work without rediscovering scope, criteria or test protocol.

## Phase 1 — Technical kill test
Target: 48 hours once headset/tooling are available.

Must prove:
- table/surface placement;
- one object grab;
- rotation/placement;
- generous snapping;
- simple product flow;
- target-hardware profiling.

Decision:
- continue with WebXR/IWSDK if it meets interaction/performance needs;
- pivot stack if it does not.

Do not build content here.

## Phase 2 — Core physical loop
Build only:
- source;
- belt/connection;
- processor;
- buffer;
- sink;
- visible queue;
- one bottleneck;
- overflow prototype.

Exit gate:
A new player can understand "stuff goes in -> line jams -> I fix it -> flow improves" without technical explanation.

## Phase 3 — First five minutes
Implement:
- diegetic onboarding;
- first reward;
- first visible problem;
- first physical intervention;
- first payoff;
- simple grade;
- one draft choice.

Test with at least five naive players.

Exit gate:
Median first successful delivery < 60 s and no participant requires an engineering explanation.

## Phase 4 — Game-feel freeze
Feature freeze.

Work only on:
- snap quality;
- animation;
- silhouettes;
- audio;
- spatial feedback;
- lighting/material coherence;
- legibility;
- error recovery.

Exit gate:
The build no longer looks or feels like a prototype.

## Phase 5 — Replayability slice
Add minimal variety:
- 2–3 contract variants;
- small draft pool;
- 4–5 turn run;
- persistence if needed.

Exit gate:
Players voluntarily start another turn in free play.

## Phase 6 — Hardening
Test:
- real Quest;
- different tables/rooms;
- seated play;
- left/right handed users;
- hand loss/reacquisition;
- pause/resume;
- performance;
- save/reload if applicable.

No new mechanics.

## Phase 7 — Submission
Prepare:
- real gameplay capture;
- <3 minute video;
- English copy;
- screenshots;
- adaptation evidence;
- release-date statement;
- checklist audit.

Internal target: submit before the final official day.

## Current next action
Run Phase 1 only after access/tooling is ready.

## Scope guard
If work does not advance the current exit gate, it is backlog.
